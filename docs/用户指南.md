# ModelForge 用户指南

## 快速开始

### 1. 启动服务

```powershell
# 启动后端 API (端口 5095)
dotnet run --project src\backend\ModelForge.Backend

# 启动 Sidecar (端口 5200)
dotnet run --project src\sidecar\ModelForge.Sidecar

# 启动 Web Add-in 开发服务器 (端口 5173)
cd src\web && npm run dev
```

### 2. 在 Office 中侧载

1. 在仓库根目录运行 `scripts\setup-office-addin-sideload.ps1`，创建本机共享目录并注册 Office TrustedCatalog。
2. 打开 Excel、PowerPoint 或 Word → 插入 → 我的加载项 → 共享文件夹 → 选择 `ModelForge`。
3. ModelForge 标签页出现在 Ribbon 上。直接复制到 WEF 缓存目录不是可靠侧载方式。

### 3. 使用功能

#### Ribbon 按钮

点击 ModelForge 标签下的 Ribbon 按钮直接执行命令：

|             | 标记公式    | `Ctrl+Alt+F` |
|             | 标记外链    | `Ctrl+Alt+L` |

#### 任务窗格

点击 Ribbon "打开任务窗格" 按钮打开侧边栏：

- **总览**: 查看 Backend 和 Sidecar 连接状态
- **命令**: 按分组浏览和执行所有命令
- **Excel**: 查看当前工作簿、工作表、选中区域信息
- **审计**: 查看审计相关命令列表
- **AIWA**: AI 写作助手对话界面
- **管理**: 用户管理和审计日志(需权限)

#### Omnibar 搜索

点击右下角搜索按钮或按 `Ctrl+Shift+P` 打开命令面板，输入关键词即时搜索所有命令。

### 4. 快捷键自定义

通过 Sidecar API 管理快捷键：

```powershell
# 查看所有快捷键（兼容原始数组）
curl http://localhost:5200/api/shortcuts

# 导出结构化快捷键映射
curl http://localhost:5200/api/shortcuts/export

# 执行命令
curl -X POST http://localhost:5200/api/execute -H "Content-Type: application/json" -d '{"commandId":"excel.fill-right","host":"excel"}'
```

### 5. 常见操作

**安全外发工作簿**:

1. 打开 Excel 工作簿
2. 点击 "安全外发" 按钮
3. 确认输出路径 → 生成 `*_SafeCopy.xlsx` 副本

**Model Check**:

1. 打开需要审计的工作簿
2. 点击 "Model Check" 按钮
3. 在任务窗格的审计面板查看结果

**Excel → PowerPoint 链接**:

1. 在 Excel 选中要链接的区域
2. 启动 PowerPoint 并打开目标演示文稿
3. 点击 "链接至 PPT" 按钮
4. 更新 Excel 数据后点击 "刷新链接"；Sidecar 会读取后端链接元数据并刷新当前本机 Office 链接

## 手工调试指南

### 一、后端 API 服务调试（:5095）

#### 1.1 启动后端

```powershell
# 方式一：直接运行
dotnet run --project src\backend\ModelForge.Backend

# 方式二：使用脚本
scripts\dev-backend.cmd

# 方式三：发布后运行
dotnet publish src\backend\ModelForge.Backend -c Release
cd publish\Backend
dotnet ModelForge.Backend.dll
```

#### 1.2 验证后端健康状态

```powershell
# 健康检查
curl http://localhost:5095/health

# 版本信息
curl http://localhost:5095/api/version

# 命令目录
curl http://localhost:5095/api/commands

# 配置读取
curl http://localhost:5095/api/config/default
```

#### 1.3 调试认证流程

```powershell
# 1. 登录获取 JWT Token
curl -X POST http://localhost:5095/api/auth/login `
  -H "Content-Type: application/json" `
  -d '{"username":"admin","password":"admin123"}'

# 2. 保存返回的 token，例如：
# {"traceId":"abc123","data":{"token":"eyJhbGc...","userId":"xxx","username":"admin","role":"Admin",...},"error":null}

# 3. 使用 Token 访问受保护接口
$token = "eyJhbGc..."  # 替换为上一步获取的 token
curl http://localhost:5095/api/auth/me `
  -H "Authorization: Bearer $token"

# 4. 访问 Admin 接口（需 Admin 角色）
curl http://localhost:5095/api/admin/users `
  -H "Authorization: Bearer $token"
```

#### 1.4 调试命令目录与分发

```powershell
# 查看预置命令
curl http://localhost:5095/api/commands

# 提交命令调度请求（真实 Office 执行仍由 Sidecar /api/execute 完成）
curl -X POST http://localhost:5095/api/commands/dispatch `
  -H "Content-Type: application/json" `
  -d '{"commandId":"excel.model-check","host":1,"userId":"developer","workbookId":"local-workbook"}'

# 查看审计日志
curl http://localhost:5095/api/admin/audit-events?count=20 `
  -H "Authorization: Bearer $token"
```

#### 1.5 常见问题排查

| 问题             | 可能原因                  | 排查步骤                                               |
| ---------------- | ------------------------- | ------------------------------------------------------ | ---------------------------- |
| 端口 5095 被占用 | 其他进程占用              | `netstat -ano                                          | findstr :5095`，杀死占用进程 |
| CORS 错误        | Web Add-in 域名不在白名单 | 检查 `appsettings.json` 和 `Program.cs` 中的 CORS 配置 |
| 认证失败 401     | Token 过期/无效           | 重新登录获取新 Token，检查 JWT Secret 配置             |
| 命令目录为空     | 未正确初始化              | 检查 `CommandCatalog` 初始化逻辑，查看控制台日志       |

#### 2.4 调试 COM 互操作

Sidecar 通过 `oleaut32!GetActiveObject` 获取运行中的 Office 实例：

1. 先启动 Excel 并打开一个工作簿
2. 启动 Sidecar（控制台会输出连接状态日志）
3. 通过 REST API 发送命令，观察控制台输出

**关键调试点**：

- Sidecar 控制台日志会显示 `GetActiveObject` 是否成功
- 如果 Office 未运行，命令会返回 503 状态码
- COM 对象释放由 `OfficeApplicationFactory` 自动管理

**调试 COM 互操作异常**：

```powershell
# 1. 确保 Excel 已打开
# 2. 发送简单命令测试
curl -X POST http://localhost:5200/api/execute `
  -H "Content-Type: application/json" `
  -d '{"commandId":"excel.insert-statistics","host":"excel"}'

# 3. 查看 Sidecar 控制台输出，定位 COM 异常
```

#### 2.5 调试全局键盘钩子

Sidecar 使用 Win32 `WH_KEYBOARD_LL` 实现全局快捷键：

1. 确保 `appsettings.json` 中 `"KeyboardHookEnabled": true`
2. 启动 Sidecar，控制台应输出键盘钩子初始化日志
3. 在任意窗口按下预设快捷键（如 `Ctrl+Alt+R`）
4. 观察 Sidecar 控制台是否输出命令执行日志

**快捷键注册机制**：

- `ShortcutRegistry` 在启动时从 `DefaultShortcutMap` 加载默认映射
- `ChordParser` 解析组合键（如 `Ctrl+Alt+R`）
- `KeyboardCommandRouter` 将快捷键路由到对应命令 ID
- `GlobalKeyboardHook` 作为 `IHostedService` 在后台运行

**调试键盘钩子异常**：

- 检查控制台是否输出 "Keyboard hook installed" 日志
- 某些安全软件可能拦截全局钩子，检查杀毒软件日志
- 快捷键冲突：确认没有其他程序占用相同快捷键组合

#### 2.6 调试 Backend 桥接客户端

Sidecar 通过 HTTP 客户端 `BackendBridgeClient` 与 Backend 通信：

```powershell
# 1. 确保 Backend 已启动在 :5095
# 2. 查看 Sidecar appsettings.json 中的 BackendBaseUrl
#    "BackendBaseUrl": "http://localhost:5095"

# 3. Sidecar 控制台会输出桥接请求日志
# 4. 可通过 Backend 审计日志验证请求是否到达
curl http://localhost:5095/api/admin/audit-events?count=20 `
  -H "Authorization: Bearer $token"
```

#### 2.7 Sidecar 端点一览

| 端点                    | 方法 | 说明                     |
| ----------------------- | ---- | ------------------------ |
| `/health`               | GET  | 健康检查                 |
| `/api/shortcuts`        | GET  | 获取所有快捷键映射       |
| `/api/shortcuts/export` | GET  | 导出结构化快捷键映射     |
| `/api/shortcuts/import` | POST | 原子导入快捷键映射       |
| `/api/execute`          | POST | 核心命令执行入口         |
| `/api/status`           | GET  | 当前 Office COM 连接状态 |

**Execute 请求体格式**：

```json
{
  "commandId": "excel.fill-right",
  "host": "excel"
}
```

**Execute 响应格式**：

```json
{
  "traceId": "abc123",
  "data": {
    "success": true,
    "commandId": "excel.fill-right",
    "message": "Command executed successfully.",
    "result": "..."
  },
  "error": null
}
```

#### 3.7 常见问题排查

| 问题               | 可能原因          | 排查步骤                                                                        |
| ------------------ | ----------------- | ------------------------------------------------------------------------------- |
| 任务窗格空白       | 开发服务器未启动  | 检查 `npm run dev` 是否运行，访问 `http://localhost:5173`                       |
| CORS 错误          | 域名不匹配        | 检查 `Program.cs` 中 CORS 策略，确认 `WithOrigins` 包含 `http://localhost:5173` |
| 图标不显示         | 资源路径错误      | 检查 `manifest` 中 `IconUrl` 指向 `http://localhost:5173/assets/icon-32.png`    |
| 侧载失败           | Office 版本/HTTPS | 尝试 HTTP manifest 或使用 Office 开发证书                                       |
| 命令执行无响应     | Sidecar 未启动    | 检查 `http://localhost:5200/health`，查看 Sidecar 控制台日志                    |
| 任务窗格与后端不通 | 后端地址配置错误  | 检查 `.env.local` 中 `VITE_MODELFORGE_API_URL`                                  |

### 四、端到端调试流程

#### 4.1 完整启动顺序

```powershell
# 第 1 步：启动后端 API
dotnet run --project src\backend\ModelForge.Backend
# 验证: curl http://localhost:5095/health

# 第 2 步：启动 Sidecar
dotnet run --project src\sidecar\ModelForge.Sidecar
# 验证: curl http://localhost:5200/health

# 第 3 步：启动 Web Add-in
cd src\web && npm run dev
# 验证: 访问 http://localhost:5173

# 第 4 步：在 Excel 中侧载 Add-in
# 插入 → 我的加载项 → 共享文件夹 → modelForge.web.xml
```

#### 4.2 调试命令执行链路

一个完整的命令执行涉及以下链路：

```
Ribbon 按钮 / 任务窗格
    ↓ (Office.js / function-file.html)
Web Add-in (React, :5173)
    ↓ (fetch → http://localhost:5200/api/execute)
Sidecar REST API (:5200)
    ↓ (COM Interop / Win32 API)
Office COM 对象 (Excel/PPT/Word)
    ↓ (可选: HTTP → http://localhost:5095)
Backend API (:5095) [审计/配置/字典]
```

**调试要点**：

1. 在 Web Add-in 浏览器控制台查看网络请求
2. 在 Sidecar 控制台查看命令执行日志
3. 在 Backend 控制台查看审计事件记录
4. 使用 `X-Trace-Id` 请求头追踪跨服务调用

#### 4.3 使用 curl 模拟完整链路

```powershell
# 1. 登录获取 Token
$loginResp = curl -X POST http://localhost:5095/api/auth/login `
  -H "Content-Type: application/json" `
  -d '{"username":"admin","password":"admin123"}' | ConvertFrom-Json
$token = $loginResp.data.token

# 2. 通过 Sidecar 执行命令
curl -X POST http://localhost:5200/api/execute `
  -H "Content-Type: application/json" `
  -d '{"commandId":"excel.fill-right","host":"excel"}'

# 3. 查看 Backend 审计日志
curl http://localhost:5095/api/admin/audit-events?count=20 `
  -H "Authorization: Bearer $token"
```

#### 4.4 调试跨应用联动（Excel → PowerPoint）

1. 在 Excel 中打开工作簿，选中要链接的区域
2. 启动 PowerPoint 并打开目标演示文稿
3. 确保 Sidecar 已启动（同时支持 Excel 和 PowerPoint COM）
4. 点击 "链接至 PPT" 按钮
5. 观察 Sidecar 控制台输出，确认 COM 对象切换正常

**关键调试点**：

- `OfficeApplicationFactory` 需同时追踪 Excel 和 PowerPoint 实例
- 跨应用命令通过 `request.Host` 字段路由到对应 Interop 服务
- 确保 Excel 和 PowerPoint 使用相同 Office 版本

# ModelForge 用户指南

## Office 启动时提示加载旧 COM/VSTO 项

当前版本使用 Web Add-in + Sidecar 架构，不再使用历史 `src/vsto` VSTO 加载项。如果 Excel 启动时提示加载：

```text
file:///D:/CODES/model-forge/src/vsto/ModelForge.Excel/bin/Debug/ModelForge.Excel.vsto
```

说明本机 Office 注册表里还有旧加载项残留。关闭 Excel / PowerPoint / Word 后，在仓库根目录运行：

```powershell
.\scripts\clear-legacy-vsto-addins.ps1
```

该脚本只清理名称或 manifest 指向 ModelForge 历史 `src/vsto` 的 Office Add-in 注册项，不删除其他第三方 Office 插件。

## Excel Ribbon 按钮无反应或执行失败

当前版本要求 Sidecar 连接 Microsoft Office 2016+/Office 2024 的桌面 COM 实例。若本机同时运行 WPS/Kingsoft Office，`Excel.Application` 可能被 WPS 注册为兼容 COM（常见表现为版本 `12.0`），Ribbon 按钮会表现为无反应、失败或提示 Excel 未运行。

复测前先关闭 WPS，并运行预检：

```powershell
cd D:\CODES\model-forge
.\scripts\check-office-runtime.ps1 -StopWps
```

预期结果：

- 进程列表中只出现 `EXCEL.EXE` / `POWERPNT.EXE` / `WINWORD.EXE`，路径位于 `C:\Program Files...\Microsoft Office\root\Office16\`。
- `http://localhost:5200/api/status` 返回 `connected=true` 且 `version=16.0`。
- 不应再出现 `wps.exe`、`et.exe`、`wpp.exe` 或 `Kingsoft\WPS Office` 路径。

若按钮仍失败，先查看 Sidecar 审计事件而不是重复侧载 manifest：

```powershell
$login = Invoke-RestMethod http://localhost:5095/api/auth/login -Method Post -ContentType 'application/json' -Body (@{username='admin';password='admin123'} | ConvertTo-Json)
$headers = @{ Authorization = "Bearer $($login.data.token)" }
Invoke-RestMethod 'http://localhost:5095/api/admin/audit-events?count=100' -Headers $headers |
  Select-Object -ExpandProperty data |
  Select-Object -ExpandProperty items |
  Where-Object { $_.eventType -like 'command.*' -or $_.commandId } |
  Select-Object recordedAtUtc,eventType,host,severity,commandId
```
