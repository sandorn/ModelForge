# ModelForge 实现路径规划


> **计划修订 (2026-06-05)**：Phase A 已全部交付，Phase B/C 多数功能超前实现。标记为 ⚠️ 的条目经评估延后或取消。ADR-004/005 已决策。
## 1. 实施原则

### 1.0 当前项目判断

当前仓库已通过\*\*Phase A 开发验证\*\*，`src/`、`manifest/`、测试工程和 CI 配置均已建立。源码骨架包含 Sidecar (45+ C# 源文件)、Backend (7+ 服务)、Web Add-in (11+ TSX 组件) 和共享 Contracts。近期工作应聚焦于 Phase A 收尾和测试覆盖提升：

1. 明确 MVP 边界和阶段验收标准。
2. 固化 Sidecar / Web Add-in / 后端桥接的技术边界。
3. 建立项目骨架、命令目录、接口契约和测试基线。
4. 通过 Excel Sidecar MVP 验证核心产品价值，再扩展到 PowerPoint、Word、AIWA 和企业后台。

### 1.1 优先级策略

1. **核心功能优先**: Excel 财务建模工具优先 (P0)。
2. **高频功能优先**: 快捷键、跨应用联动、Deck Check 等。
3. **可独立运行**: 每个模块可独立测试和发布。
4. **平滑升级**: 兼容已有代码，便于后续扩展。

### 1.2 开发模式

- 阶段式开发，每个阶段交付可用功能。
- 单元测试覆盖关键功能。
- 持续集成确保代码质量。

## 2. 技术路线

### 2.1 架构设计：Sidecar + Office JS API 混合架构 + 后端桥接

#### 2.1.1 架构选型理由

| 能力需求                                        | Web Add-in  | Sidecar (.NET 10 + 原生 COM) | 结论                     |
| ----------------------------------------------- | ----------- | ---------------------------- | ------------------------ |
| Keyboard Shortcuts (快捷键)                     | 部分支持    | ✅ Win32 全局钩子             | **P0级刚需，Sidecar 主责** |
| Link Excel to PowerPoint/Word (深度COM引用绑定) | ❌ 能力有限 | ✅ 原生 COM 完全支持     | Sidecar 实现              |
| 颜色板、共享库检索                              | ✅ 轻量更新 | ❌ 需重新安装                 | Web 更灵活               |
| Deck Check 报告生成界面                         | ✅ 热更新   | ❌ 需重新安装                 | Web 更优                 |
| Ribbon 菜单融合                                 | ✅ 支持     | N/A (通过 manifest 驱动)      | Web Add-in 承载全部 Ribbon |

**重要澄清**：Sidecar 与 Web Add-in 运行在不同进程，禁止直接通信。两者的功能协调必须通过**后端 API 桥接** (ASP.NET Core 10) 和 Sidecar localhost REST API 实现。

#### 2.1.2 功能分工图（2026 重构版）

```text
├─────────────────────────────┴───────────────────────────────────┤
│ Sidecar 负责：                      Web Add-in 负责：              │
│ ├── 全局键盘钩子 (Win32)            ├── Admin Console             │
│ ├── 原生 COM 互操作            ├── Shared Libraries          │
│ ├── 公式追踪 + Model Check          ├── Corporate Dictionary      │
│ ├── 文件优化 + Prepare to Share     ├── Dashboard 统计            │
│ ├── Power Tools                     ├── Omnibar 速查栏            │
│ ├── Visualizations                  ├── AIWA 前端 UI              │
│ ├── 高级图表 Chart Add-ons          └── 企业策略下发              │
│ └── PPT/Word 底层交互                                             │
│                                                                   │
│ Backend 负责：认证、配置、审计、链接元数据、字典、命令桥接、遥测     │
└─────────────────────────────────────────────────────────────────┘
```

#### 2.1.3 技术栈

| 层级              | 技术选型                           | 说明               |
| ----------------- | ---------------------------------- | ------------------ |
| **Sidecar 运行时**| .NET 10 Minimal API              | COM 操作 + 快捷键   |
| **COM 互操作**    | 原生 COM 2.x (MIT)                | 🆕 版本无关 COM 代理 |
| **Office JS API** | Office.js + Office Add-in Manifest | Web 插件           |
| **后端桥接 API**  | ASP.NET Core 10 (REST + SignalR)    | 跨进程通信         |
| **前端框架**      | React 18 / TypeScript              | Web Add-in UI      |
| **UI 组件库**     | Fluent UI React                    | Microsoft 设计系统 |
| **构建工具**      | Vite                               | Web Add-in 打包    |
| **数据库**        | PostgreSQL / SQL Server            | 配置与日志         |

#### 2.1.4 项目结构


### 2.2 开发实施风险与对策

| 风险                              | 影响 | 缓解措施                                                |
| --------------------------------- | ---- | ------------------------------------------------------- |
| Sidecar 与 Web Add-in 进程隔离     | 高   | 强制使用 Sidecar localhost REST + 后端 API 桥接 |
| Sidecar 与 Office 进程权限不匹配 | 中   | 原生 COM 内建重试 + 诊断日志 |
| .NET 运行时依赖                   | 中   | Self-contained 部署，无外部运行时依赖 |
| 快捷键冲突                        | 低   | 提供冲突检测 UI，允许用户自定义                         |

## 6. 风险与应对

| 风险类别              | 具体描述                         | 缓解策略                                         |
| --------------------- | -------------------------------- | ------------------------------------------------ |
| **Office 版本兼容性** | 不同版本 Office COM 接口行为差异 | 覆盖 Office 2016/2019/365 测试，关键功能回退方案 |
| **Sidecar 部署权限**   | 用户可能无管理员权限安装 Windows Service | 提供用户级 Tray App 模式作为降级方案        |
| **快捷键冲突**        | 与其他全局热键软件冲突           | 内置冲突检测 + 提醒用户自定义                    |
| **跨应用链接稳定性**  | Excel 与 PPT 链接断裂难以追踪    | 增加链接健康状态检查，自动修复向导               |
| **AI 数据安全**       | 客户不允许将内容发送至公有 LLM   | 提供私有化部署选项 (Llama3)，支持 BYOK           |
| **后端桥接性能**      | 高频调用 API 可能延迟            | 关键路径使用本地缓存，批量操作合并请求           |

## 10. 测试策略

### 10.1 测试分层

1. **单元测试**：后端服务、命令解析、配置合并、字典规则、公式分析辅助逻辑。
2. **集成测试**：Sidecar 调用后端、Web 调用后端、链接元数据读写、审计事件上报。
3. **Office 手工回归**：Excel/PowerPoint/Word 真实宿主中的 Ribbon、COM 操作、文件保存与刷新。
4. **兼容性测试**：Office 2016、Office 2019、Microsoft 365；32/64 位 Office 需明确支持策略。
5. **性能测试**：大工作簿扫描、跨应用刷新、冷启动耗时、内存泄漏和 COM 对象释放。
