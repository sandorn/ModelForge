# ModelForge 管理员指南

## 部署架构

| 组件 | 默认地址 | 部署形态 |
| --- | --- | --- |
| Office Web Add-in | Office WebView2 | 静态文件 + Office manifest |
| Sidecar | `http://localhost:5200` | Windows Service |
| Backend API | `http://localhost:5095` | Windows Service |
| Database | 配置决定 | In-memory / SQLite / PostgreSQL |

## 构建 MSI

前置条件：

- .NET 10 SDK
- Node.js 20+
- WiX Toolset v5: `dotnet tool install --global wix`

在仓库根目录运行：

```powershell
.\scripts\build-installer.ps1 -Configuration Release
```

输出文件：

| 文件 | 说明 |
| --- | --- |
| `ModelForge.msi` | 可安装 MSI 包 |
| `ModelForge.wixpdb` | WiX 调试数据库 |
| `publish\Backend\ModelForge.Backend.exe` | Backend 单文件服务 |
| `publish\Sidecar\ModelForge.Sidecar.exe` | Sidecar 单文件服务 |
| `publish\Web\` | Web Add-in 静态资源 |
| `publish\manifest\modelForge.web.xml` | Office manifest |

验证 MSI：

```powershell
wix msi validate ModelForge.msi
```

## 安装与卸载

以下命令需在“以管理员身份运行”的 PowerShell 中执行。

推荐先运行完整管理员回归脚本：

```powershell
.\scripts\test-msi-admin.ps1
```

该脚本会解析 `ModelForge.msi` 的绝对路径，安装 MSI，验证 `ModelForge.Sidecar` / `ModelForge.Backend` Windows Service 和 `/health`，再执行卸载并确认服务已移除；日志写入 `artifacts\manual-e2e\msi-install-admin.log` 与 `artifacts\manual-e2e\msi-uninstall-admin.log`。

交互安装：

```powershell
$msi = (Resolve-Path ".\ModelForge.msi").Path
msiexec /i $msi /l*v "$PWD\install.log"
```

静默安装：

```powershell
$msi = (Resolve-Path ".\ModelForge.msi").Path
msiexec /i $msi /quiet /l*v "$PWD\install.log"
```

卸载：

```powershell
$msi = (Resolve-Path ".\ModelForge.msi").Path
msiexec /x $msi /l*v "$PWD\uninstall.log"
```

默认安装目录：

```text
C:\Program Files\ModelForge\
```

安装后服务：

```powershell
sc query ModelForge.Sidecar
sc query ModelForge.Backend
curl http://localhost:5200/health
curl http://localhost:5095/health
```

> 当前 MSI 为 `perMachine` 安装包。非管理员 PowerShell 执行会在 `InstallFinalize` 阶段返回 Windows Installer `1925 / 1603`（权限不足），这是预期失败路径。MSI 直接传入 `.\ModelForge.msi` 等相对路径时也可能在进入安装序列前返回 Windows Installer `1324`；请使用上面的脚本或先通过 `Resolve-Path` 转为绝对路径。

推荐回归脚本：

```powershell
.\scripts\test-msi-admin.ps1
```

## 管理员 API 手工验证

默认本地管理员账号：`admin/admin123`。以下命令用于验证真实 Backend 管理链路。

```powershell
$login = Invoke-RestMethod -Method Post -Uri http://localhost:5095/api/auth/login `
  -ContentType 'application/json' `
  -Body (@{ username='admin'; password='admin123' } | ConvertTo-Json)
$token = $login.data.token
$headers = @{ Authorization = "Bearer $token" }

Invoke-RestMethod -Method Get -Uri http://localhost:5095/api/admin/users -Headers $headers

$newUser = Invoke-RestMethod -Method Post -Uri http://localhost:5095/api/admin/users `
  -Headers $headers -ContentType 'application/json' `
  -Body (@{ username='ops-check'; password='ChangeMe123!'; role='Analyst' } | ConvertTo-Json)

Invoke-RestMethod -Method Put -Uri "http://localhost:5095/api/admin/users/$($newUser.data.id)/toggle" -Headers $headers
Invoke-RestMethod -Method Get -Uri 'http://localhost:5095/api/admin/roles' -Headers $headers
Invoke-RestMethod -Method Get -Uri 'http://localhost:5095/api/admin/audit-events?count=20' -Headers $headers
Invoke-RestMethod -Method Get -Uri 'http://localhost:5095/api/admin/audit-events/summary?hours=168' -Headers $headers
Invoke-RestMethod -Method Post -Uri 'http://localhost:5095/api/admin/audit-events/retention' `
  -Headers $headers -ContentType 'application/json' `
  -Body (@{ retentionDays = 90; dryRun = $true } | ConvertTo-Json)
Invoke-RestMethod -Method Get -Uri 'http://localhost:5095/api/admin/diagnostics' -Headers $headers
Invoke-WebRequest -Uri 'http://localhost:5095/api/admin/diagnostics/bundle' -Headers $headers -OutFile .\modelforge-diagnostics.json
```

预期：所有成功响应均为 `ApiEnvelope<T>`；重复创建同名用户返回 `409`，非法角色返回 `400`，不存在用户启停返回 `404`，错误体包含 `traceId` 和 `error`。Admin Console 的“角色权限”面板调用 `/api/admin/roles` 展示内置角色和权限矩阵，当前只读；“审计日志”面板调用 `/api/admin/audit-events/summary` 展示最近事件类型、用户、宿主 Top 10、时间趋势条形图和事件类型 × 宿主热力图，并可预览/执行审计保留清理。Admin Console 的“诊断”面板同样调用 `/api/admin/diagnostics`，只展示版本、数据库连接、命令/链接/字典/审计计数、审计保留策略和脱敏配置摘要，不包含密钥、认证令牌或工作簿内容；“下载诊断包”按钮调用 `/api/admin/diagnostics/bundle`，下载 JSON 文件，包含运行时信息和最近审计事件，不打包本机日志文件。

## 遥测关闭开关

`default` 配置中的 `TelemetryEnabled=false` 为默认值。关闭时，普通 `Information` 级使用统计事件会返回 `recorded=false` 且不写入审计存储；`Warning` 及以上、安全、认证和管理事件仍会记录。

```powershell
Invoke-RestMethod -Method Put -Uri 'http://localhost:5095/api/config/default' `
  -Headers $headers -ContentType 'application/json' `
  -Body (@{ values = @{ TelemetryEnabled = 'false' }; updatedBy = 'admin' } | ConvertTo-Json -Depth 3)
```

只有在完成内部告知、数据范围说明和审批后，才建议将 `TelemetryEnabled` 切换为 `true`。

Web Add-in 的显式用户点击会以 `ui.*` 事件 best-effort 上报 `/api/audit-events`，覆盖导航、命令执行、快捷键配置、Deck Check、链接刷新、Admin 审计/诊断、Corporate Dictionary 和 AIWA 操作。该类事件属于普通 `Information` 级使用统计，受 `TelemetryEnabled` 控制；上报失败不会阻塞用户操作。

## 审计日志保留策略

默认审计日志保留 `90` 天。可通过 Backend `default` 配置或环境变量 `AuditRetentionDays` 调整；合法范围为 `1..3650`。建议先 `dryRun=true` 预览匹配数量，再执行真实清理。

```powershell
# 设置默认保留天数
Invoke-RestMethod -Method Put -Uri 'http://localhost:5095/api/config/default' `
  -Headers $headers -ContentType 'application/json' `
  -Body (@{ values = @{ AuditRetentionDays = '90' }; updatedBy = 'admin' } | ConvertTo-Json -Depth 3)

# 预览清理，不删除
Invoke-RestMethod -Method Post -Uri 'http://localhost:5095/api/admin/audit-events/retention' `
  -Headers $headers -ContentType 'application/json' `
  -Body (@{ dryRun = $true } | ConvertTo-Json)

# 执行清理
Invoke-RestMethod -Method Post -Uri 'http://localhost:5095/api/admin/audit-events/retention' `
  -Headers $headers -ContentType 'application/json' `
  -Body (@{ retentionDays = 90; dryRun = $false } | ConvertTo-Json)
```

真实清理会删除早于 `cutoffUtc=UtcNow-retentionDays` 的审计事件，并记录 `admin.audit.retention.pruned` 管理审计事件。该能力支持 InMemory、SQLite 和 PostgreSQL 审计存储；正式生产仍需结合数据库备份、归档和审计完整性保护策略。

## Sidecar 执行审计

Sidecar `/api/execute` 会自动向 Backend `/api/audit-events` 上报关键执行事件：成功为 `command.executed`，输入校验失败为 `command.validation_failed`，Office 未运行或 COM 异常为 `command.failed`。Backend 按 `TelemetryEnabled` 和严重级别策略决定是否落库；审计上报失败只记录 Sidecar 日志，不阻塞本机命令响应。

```powershell
Invoke-RestMethod -Method Put -Uri 'http://localhost:5095/api/config/default' `
  -Headers $headers -ContentType 'application/json' `
  -Body (@{ values = @{ TelemetryEnabled = 'true' }; updatedBy = 'admin' } | ConvertTo-Json -Depth 3)

Invoke-RestMethod -Method Post -Uri 'http://localhost:5200/api/execute' `
  -Headers @{ 'X-ModelForge-Sidecar-Token' = 'replace-with-local-token' } `
  -ContentType 'application/json' `
  -Body (@{ commandId=''; host='excel' } | ConvertTo-Json)

Invoke-RestMethod -Method Get -Uri 'http://localhost:5095/api/admin/audit-events?count=20' -Headers $headers
```

预期：第二步返回 `400 ApiEnvelope<SidecarExecuteResponse>`；第三步可看到 `eventType=command.validation_failed`、`actorId=local-sidecar` 的审计事件。若未启用 `Sidecar:LocalApiToken`，可省略 `X-ModelForge-Sidecar-Token` 请求头。

## Backend 管理写操作审计

Backend 登录和管理写操作会记录 `auth.*` / `admin.*` 审计事件：登录成功、登录失败、用户创建/启停、配置更新、Corporate Dictionary 术语新增/删除/导入。管理操作 `actorId` 为 JWT `sub`（当前本地用户 ID），登录失败 `actorId` 为尝试登录的用户名，`host=Web`，`resourceId` 指向用户 ID、配置 scope 或术语 ID。

```powershell
Invoke-RestMethod -Method Get -Uri 'http://localhost:5095/api/admin/audit-events?count=50' -Headers $headers |
  Select-Object -ExpandProperty data |
  Select-Object -ExpandProperty items
```

预期可看到 `auth.login.succeeded`、`auth.login.failed`、`admin.user.created`、`admin.user.toggled`、`admin.config.updated`、`admin.dictionary.term.upserted`、`admin.dictionary.imported` 或 `admin.dictionary.term.deleted`。这些认证/管理审计属于安全/管理事件，不受普通信息级遥测关闭影响。

## Sidecar 服务令牌

如需让 Sidecar 在 Deck Check 中自动读取 Backend Corporate Dictionary，需要在 Backend 和 Sidecar 配置同一高熵服务令牌。默认空值表示禁用服务级读取。

Backend 配置：

```json
{
  "ModelForge": {
    "ServiceToken": "replace-with-random-32-byte-token"
  }
}
```

Sidecar 配置：

```json
{
  "Sidecar": {
    "ServiceToken": "replace-with-random-32-byte-token"
  }
}
```

验证：

```powershell
Invoke-WebRequest -Uri 'http://localhost:5095/api/dictionary/service-export' -Headers @{ 'X-Service-Token' = 'replace-with-random-32-byte-token' }
```

该端点不接受管理员 JWT 代替服务令牌；不要把服务令牌写入前端代码或 Office manifest。

## Sidecar 本地 API 令牌

如需保护本机 Sidecar `/api/*` 端点，可配置 `Sidecar:LocalApiToken`。默认空值保持本地开发兼容；启用后 Web Add-in 任务窗格和 Ribbon function-file 必须在请求头携带 `X-ModelForge-Sidecar-Token`。`/health` 不受保护，供服务探活使用。

Sidecar 配置：

```json
{
  "Sidecar": {
    "LocalApiToken": "replace-with-random-32-byte-token"
  }
}
```

Web Add-in 配置方式：

```powershell
# 任务窗格构建期注入，适合企业托管 Web Add-in
$env:VITE_MODELFORGE_SIDECAR_TOKEN = "replace-with-random-32-byte-token"
npm run build

# 任务窗格也可在“Excel / Sidecar 本地令牌”面板保存。

# Ribbon function-file 适合在当前 Office WebView 用户上下文中写入 localStorage
localStorage.setItem("modelforge_sidecar_token", "replace-with-random-32-byte-token")
```

验证：

```powershell
Invoke-WebRequest -Uri 'http://localhost:5200/api/shortcuts/export' -Headers @{ 'X-ModelForge-Sidecar-Token' = 'replace-with-random-32-byte-token' }
```

该令牌只用于本机 Sidecar API 保护，不替代 Backend JWT，也不要提交到仓库或写入共享 manifest。

## Corporate Dictionary 管理

Admin Console 的 Corporate Dictionary 面板支持：

- 术语新增/删除、分类、级别、替换建议和可选正则表达式。
- 样例文本检查和命中高亮。
- JSON 导入/导出：直接对应 Backend `/api/dictionary/export` 与 `/api/dictionary/import`。
- CSV/XLSX 模板导入/导出：前端按模板列解析为同一 JSON 导入请求，不新增后端二进制接口。

CSV/XLSX 模板列：

| 列名 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 否 | 术语 ID，留空时后端生成。 |
| `term` | 是 | 术语文本。 |
| `replacement` | 否 | 推荐替换文本。 |
| `regexPattern` | 否 | 可选正则表达式。 |
| `category` | 否 | 分类，默认 `General`。 |
| `severity` | 否 | 级别，默认 `Warning`。 |

```text
C:\Program Files\ModelForge\manifest\modelForge.web.xml
```

Office Add-in 仍需通过受信任目录、组策略或 Microsoft 365 管理中心分发。手工 sideload 可复制 manifest 到：

```powershell
Copy-Item "C:\Program Files\ModelForge\manifest\modelForge.web.xml" "$env:LOCALAPPDATA\Microsoft\Office\WEF\"
```
