## 一、🔴 Critical 问题（必须立即修复）

### 1.1 COM 对象生命周期管理 — Sidecar 崩溃根源

| #    | 问题                                                                  | 文件                                     | 影响                     |
| ---- | --------------------------------------------------------------------- | ---------------------------------------- | ------------------------ |
| C-01 | `FinalReleaseComObject` 强制释放运行中 Office 实例引用                | `Interop/OfficeApplicationFactory.cs:62` | Office 意外崩溃          |
| C-02 | `ExcelInteropService.Dispose()` 释放共享的 `OfficeApplicationFactory` | `Interop/ExcelInteropService.cs:90`      | PPT/Word 连接中断        |
| C-03 | `PrepareToShare` 中 `finally` 块重复 `Close()` 工作簿                 | `Optimization/PrepareToShare.cs:108-114` | 文件锁定、Excel 进程残留 |

**修复方案**:

```csharp
// OfficeApplicationFactory.cs — 移除 FinalReleaseComObject
// GetActiveObject 返回的是运行中 Office 实例的引用，
// Sidecar 不应释放它。移除 _comObjects 跟踪和 Dispose 中的释放逻辑。

// ExcelInteropService.cs — 仅清理本地缓存
public void Dispose()
{
    if (_excelApp != null && Marshal.IsComObject(_excelApp))
    {
        while (Marshal.ReleaseComObject(_excelApp) > 0) { }
        _excelApp = null;
    }
}
```

```csharp
// JwtService.cs — 强制要求配置
public string SecretKey { get; set; } = throw new InvalidOperationException(

using BCrypt.Net;
var hash = BCrypt.Net.BCrypt.HashPassword(password);

```

## 七、架构优化建议

### 7.1 数据库持久化（最高优先级）

当前所有数据存储在内存中，应用重启后全部丢失。建议：

1. 选择 PostgreSQL（docker-compose 已配置）
2. 使用 Entity Framework Core 或 Dapper
3. 实现迁移脚本和种子数据
4. 替换所有 `InMemory*` 为数据库实现

### 7.2 认证升级

1. 集成 ASP.NET Core Identity
2. 支持 OAuth2/OIDC（SSO）
3. JWT Token 黑名单/撤销机制
4. 多因素认证（MFA）

### 7.3 可观测性

1. 集成 OpenTelemetry 分布式追踪
2. Prometheus + Grafana 指标监控
3. Serilog + Seq/ELK 日志聚合
4. 健康检查增强（依赖检查）

### 7.4 前端架构

1. 添加 React Testing Library 单元测试
2. 添加 Playwright/Cypress E2E 测试
3. 路由懒加载减少首屏体积
4. 国际化（i18n）支持

## 八、总结

ModelForge 项目整体架构清晰，模块划分合理，技术选型现代（.NET 10 + React 18 + TypeScript）。但存在以下关键风险需要立即关注：

1. **COM 对象泄漏** — 可能导致 Office 崩溃，是 Sidecar 稳定性的最大威胁
2. **硬编码密钥** — JWT 默认密钥和弱密码使认证形同虚设
3. **测试覆盖严重不足** — 15+ 模块零测试，无法保障代码质量
4. **InMemory 存储** — 生产环境必须替换为数据库持久化

建议按照上述优先级路线图逐步修复，Phase 1 的紧急修复应在下一个开发周期内完成。
