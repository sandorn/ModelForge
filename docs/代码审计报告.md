### 1.2 Critical 严重问题

#### 🔴 T-001: Backend Smoke Tests 未使用测试框架

- **文件**: `tests/backend/ModelForge.Backend.SmokeTests/Program.cs`
- **行号**: 全文件 (1-27)
- **问题**: 烟测使用 `static void Main` 脚本模式而非 xUnit/NUnit 测试框架。`Ensure()` 方法直接 `throw` + `Environment.ExitCode = 1`，无法被 CI 测试运行器识别。
- **影响**: CI 管道中 `dotnet test` 不会执行此烟测；测试覆盖率统计完全忽略此模块。
- **建议**: 迁移到 xUnit `[Fact]` 测试类，使用 `HttpClient` 实际调用后端 API 端点。

```csharp
// 当前 (脚本式)
static void Ensure(bool condition, string message) { ... }

// 建议 (xUnit)
[Fact]
public async void CommandCatalog_HasMinimumCount()
{
    var catalog = new CommandCatalog();
    var commands = catalog.GetAll();
    Assert.True(commands.Count >= 20, "阶段一至少应定义 20 个 Excel 高频命令。");
}
```

#### 🔴 T-002: PowerToolsTests 测试的是私有辅助函数而非真实业务逻辑

- **文件**: `tests/sidecar/ModelForge.Sidecar.Tests/PowerToolsTests.cs`
- **行号**: 31-80
- **问题**: 测试类在文件底部定义了与 Sidecar 生产代码**完全相同逻辑**的私有辅助函数 (`IsIfErrorWrapped`, `WrapWithIfError`, `UnwrapIfError`, `ParseFormatType`)，测试的是**测试代码自身**而非 Sidecar 生产代码。
- **影响**: 测试覆盖率报告对 Sidecar `PowerTools/` 目录显示 0%；这些测试对生产代码变更零保护。
- **建议**: 移除文件底部的私有辅助函数，改为引用 `ModelForge.Sidecar.PowerTools.IfErrorWrapper` 等真实生产类。如果生产代码是 `internal`，使用 `[InternalsVisibleTo]` 暴露给测试项目。

```csharp
// 当前 (测试自己的副本)
private static bool IsIfErrorWrapped(string formula) { ... } // 重复实现

// 建议 (测试真实代码)
using ModelForge.Sidecar.PowerTools;

[Fact]
public void IsIfErrorWrapped_DetectsCorrectly()
{
    var result = IfErrorWrapper.IsIfErrorWrapped("=IFERROR(A1+B1,0)");
    Assert.True(result);
}
```

## 三、Docker 安全审计

### 3.1 Critical 严重问题

#### 🔴 DC-001: docker-compose.yml 中 JWT Secret 使用默认值

- **文件**: `docker-compose.yml`
- **行号**: 27
- **问题**: `Jwt__SecretKey` 默认值为 `ModelForge-Production-Secret-ChangeMe-Min32Chars!!`。这是一个**明显是占位符**的字符串，如果部署者不修改 `.env` 文件，所有 JWT 令牌可被任何人伪造。
- **影响**: 完全的身份认证绕过。攻击者可以生成任意 JWT 令牌访问所有 API。
- **建议**:
  1. 移除默认值，强制要求提供环境变量
  2. 在启动时验证 JWT Secret 长度 ≥ 32 字符
  3. 添加健康检查拒绝使用默认密钥启动

```yaml
# 建议修改
environment:
  Jwt__SecretKey: ${MODELFORGE_JWT_SECRET} # 无默认值，强制要求
```

#### 🔴 DC-002: PostgreSQL 数据库密码使用弱默认值

- **文件**: `docker-compose.yml`
- **行号**: 11
- **问题**: `POSTGRES_PASSWORD` 默认值为 `modelforge-dev`。这是一个简单、可预测的密码。
- **影响**: 如果 Docker 容器暴露到网络（端口 5432 在 `ports` 中映射），攻击者可暴力破解。
- **建议**:
  1. 移除默认密码，使用 `${MODELFORGE_DB_PASSWORD}` 强制环境变量
  2. 生产环境不应映射数据库端口到宿主机

#### 🟠 DC-003: Backend Dockerfile 未使用多阶段构建的最佳实践

#### 🟠 DC-004: Web Dockerfile 中 package-lock.json 复制路径错误

- **文件**: `docker/Web.Dockerfile`
- **行号**: 5
- **问题**: `COPY src/web/package.json src/web/package-lock.json* ./` — 通配符 `*` 在 Docker COPY 中不工作。如果 `package-lock.json` 不存在（首次构建），命令会静默失败导致 `npm ci` 失败。
- **建议**: 移除通配符，改为 `COPY src/web/package-lock.json ./`，并确保文件存在。

#### 🟠 DC-005: Nginx 容器以 root 用户运行

- **文件**: `docker/Web.Dockerfile`

- **文件**: `docker-compose.yml`
- **行号**: 37
- **问题**: Ollama 端口 `11434` 映射到宿主机。私有大模型 API 不应直接暴露。
- **建议**: 仅通过 Backend 容器内部网络访问，移除 `ports` 映射。

#### 🟡 DC-008: 数据库卷未设置权限

- **文件**: `docker-compose.yml`
- **行号**: 13
- **问题**: `pgdata` 卷以默认权限挂载，PostgreSQL 容器内以 `postgres` 用户运行，但卷所有权可能不匹配。
- **建议**: 添加 `user` 配置或 volume 驱动选项。

### 3.4 Low 严重问题

#### 🟢 DC-009: 缺少健康检查对 Backend 和 Web 服务

- **文件**: `docker-compose.yml`
- **问题**: 仅 `postgres` 服务有 `healthcheck`。Backend 和 Web 服务无健康检查，`depends_on` 的 `condition: service_healthy` 对 Backend 无效（因为 Backend 依赖 postgres 健康）。
- **建议**: 为 Backend 添加 `/health` 端点健康检查。

#### 🟢 DC-010: Dockerfile 未使用固定标签版本

- **文件**: `docker-compose.yml` 行 34
- **问题**: `ollama/ollama:latest` 使用 `latest` 标签，可能导致不可复现构建。
- **建议**: 使用固定版本如 `ollama/ollama:0.2.0`。

### 4.1 High 严重问题

#### 🟠 C-001: Backend csproj 引用 JWT 包版本与目标框架不匹配

- **文件**: `src/backend/ModelForge.Backend/ModelForge.Backend.csproj`

- **文件**: `tests/sidecar/ModelForge.Sidecar.Tests/ModelForge.Sidecar.Tests.csproj`
- **行号**: 22-24
- **问题**: 虽然有 `<ProjectReference>` 到 Sidecar 项目，但 `PowerToolsTests.cs` 未使用它（测试的是私有副本）。这导致测试对生产代码变更零保护。
- **建议**: 修复 `PowerToolsTests.cs` 以引用真实生产代码。

### 4.2 Medium 严重问题

#### 🟡 C-003: 缺少 `.editorconfig` 统一代码风格

- **文件**: 项目根目录
- **问题**: 未找到 `.editorconfig` 文件。不同开发者可能使用不同的缩进、行尾、编码设置。
- **建议**: 添加 `.editorconfig` 定义 C# 和 TypeScript 代码风格。

#### 🟡 C-004: 缺少 `.gitignore` 排除 `publish/` 目录

- **文件**: 项目根目录
- **问题**: `publish/` 目录存在于仓库中（包含已编译的 DLL 和配置文件）。构建产物不应提交到版本控制。
- **建议**: 在 `.gitignore` 中添加 `publish/`、`bin/`、`obj/`。
